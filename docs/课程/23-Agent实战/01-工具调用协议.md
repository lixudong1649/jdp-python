# 23.1 工具调用协议

> 前置：11. minimal_agent、9. 类型注解 · 约 40 分钟 · 官方对应：[Python 教程 — 异常](https://docs.python.org/zh-cn/3/tutorial/errors.html) · 核对日期 2026-10-18

## 目标

- 理解 Agent **工具调用** 闭环：模型输出 `tool_use` → 本地按 **name** 查注册表执行 → 把 **tool_result** 追加进对话。
- 会把 **JSON Schema** 描述的参数与 Python 函数签名对齐；未注册名称应明确失败。
- 对照 `examples/agent/minimal_agent.py` 的 `TOOL_FUNCTIONS` 与阶段 23 包的 `REGISTRY`。
- Agent 侧示例以静态块展示；课内 `python run` 练注册表与分发逻辑。

## 核心概念

### 注册表：name → callable

```python
REGISTRY: dict[str, object] = {}

def register(name: str, fn):
    REGISTRY[name] = fn

def run_tool(name: str, **kwargs):
    return REGISTRY[name](**kwargs)

register("echo", lambda text: text)
print(run_tool("echo", text="hi"))
```

### 装饰器注册（阶段 23 包）

```python
from collections.abc import Callable
from typing import Any

REGISTRY: dict[str, Callable[..., Any]] = {}

def tool(name: str):
    def deco(fn):
        REGISTRY[name] = fn
        return fn
    return deco

@tool("echo")
def echo(text: str) -> str:
    return text
```

### 课内可运行：最小分发

```python run
TOOLS = {"get_weather": lambda city: f"{city}:晴"}

def dispatch(name: str, **kwargs):
    if name not in TOOLS:
        raise KeyError(name)
    return TOOLS[name](**kwargs)

print(dispatch("get_weather", city="上海"))
```

### Schema 与参数名一致

模型根据 `input_schema.properties` 生成 JSON；Python 侧用 `**kwargs` 或显式参数接收。

```python run
schema = {
    "type": "object",
    "properties": {"city": {"type": "string"}},
    "required": ["city"],
}

def get_weather(city: str) -> str:
    return f"{city}:晴"

payload = {"city": "北京"}
assert "city" in schema["required"]
print(get_weather(**payload))
```

## 易错点

- **工具名大小写不一致**：schema 里 `get_weather`，注册表写成 `GetWeather` 会 KeyError。
- **参数类型未转换**：模型可能传字符串数字；要在工具内 `int()` 或 Pydantic 校验。
- **把工具返回值直接当最终回答**：多轮里工具结果还要作为 `user`/`tool` 消息送回模型。
- **在注册表里放不可序列化对象**：注册表应只放可调用函数，不要放客户端实例除非线程安全。

## 读代码

阶段 23 [`mini_agent/tools.py`](../../../examples/项目/23-mini-agent包/mini_agent/tools.py) 与 [`runner.py`](../../../examples/项目/23-mini-agent包/mini_agent/runner.py)：

```python
from __future__ import annotations

from collections.abc import Callable
from typing import Any

ToolFn = Callable[..., Any]

REGISTRY: dict[str, ToolFn] = {}


def tool(name: str) -> Callable[[ToolFn], ToolFn]:
    def deco(fn: ToolFn) -> ToolFn:
        REGISTRY[name] = fn
        return fn

    return deco


@tool("echo")
def echo(text: str) -> str:
    return text
```

```python
from __future__ import annotations

from mini_agent.tools import REGISTRY


def run_tool(name: str, **kwargs: object) -> object:
    if name not in REGISTRY:
        raise KeyError(name)
    return REGISTRY[name](**kwargs)
```

对照 `examples/agent/minimal_agent.py`：`TOOL_FUNCTIONS = {"get_weather": get_weather}` 是同一模式的扁平 dict；包版本用装饰器在 **定义函数时** 副作用写入 `REGISTRY`，便于新增工具只改 `tools.py`。

## 练习

### 练习 1：注册表调用

```python exercise id=s23-l01-tool
# --- starter ---
REG: dict[str, object] = {}

def run(name: str, *args, **kwargs):
    raise NotImplementedError
# --- solution ---
REG: dict[str, object] = {}

def run(name: str, *args, **kwargs):
    fn = REG[name]
    return fn(*args, **kwargs)

REG["echo"] = lambda x: x
# --- check ---
assert run("echo", "a") == "a"
```

### 练习 2：安全分发

```python exercise id=s23-l01-dispatch
# --- starter ---
def safe_run(reg: dict[str, object], name: str, **kw):
    return None
# --- solution ---
def safe_run(reg: dict[str, object], name: str, **kw):
    if name not in reg:
        raise KeyError(name)
    fn = reg[name]
    return fn(**kw)
# --- check ---
assert safe_run({"echo": lambda text: text}, "echo", text="x") == "x"
```

### 从脚本到包

`minimal_agent.py` 适合端到端演示；`mini_agent` 包把**注册**与**执行**拆文件，方便单测 `run_tool` 而不 mock 网络。新增工具时只改 `tools.py` 并补测试，runner 保持稳定接口。

工具 docstring 会进入 schema 的 description 字段（若你手写 schema）；保持一句话说明用途即可。参数名与 Python 形参不一致时，模型生成的 JSON 会对不上，注册前用单元测试喂一组假 payload 验证。

`__all__` 控制 `from mini_agent import *` 的导出面，阅读包 API 时以 `__init__.py` 为准。
