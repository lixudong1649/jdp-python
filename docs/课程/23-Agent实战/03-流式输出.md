# 23.3 流式输出

> 前置：10.1 生成器、23.2 错误处理 · 约 35 分钟 · 官方对应：[迭代器](https://docs.python.org/zh-cn/3/tutorial/classes.html#iterators) · 核对日期 2026-10-18

## 目标

- 理解 **流式响应**：模型 token 分块到达，终端可边收边打印，提升体感速度。
- 用 **生成器** 表达增量事件；累积完整文本后再解析 `tool_use` JSON。
- 知道流式下 **tool call 可能分片**，需要缓冲区拼接完整参数再 `run_tool`。
- 与 `minimal_agent.py` 非流式 `messages.create` 对照，明确何时切换 `stream=True`。
- 能解释为何 CI 不测真实流式 SDK 事件。

## 核心概念

### 生成器模拟 token 流

```python run
def token_stream():
    for piece in ("你", "好", "，", "世界"):
        yield piece

buf = []
for t in token_stream():
    buf.append(t)
print("".join(buf))
```

### 边打印边累积

```python run
def stream_and_collect():
    chunks = []
    for c in ("A", "B", "C"):
        chunks.append(c)
        yield c
    return "".join(chunks)

collected = []
for part in stream_and_collect():
    collected.append(part)
print("".join(collected))
```

### 静态：事件循环伪代码

```python
# 概念：SDK stream 返回事件迭代器
def handle_stream(events):
    text_parts = []
    for event in events:
        if event["type"] == "text_delta":
            text_parts.append(event["text"])
            print(event["text"], end="", flush=True)
    return "".join(text_parts)
```

### 课内可运行：分片 JSON 缓冲

工具参数若以字符串分片到达，需拼接后再 `json.loads`：

```python run
import json

fragments = ['{"city":', ' "上海"}']
raw = "".join(fragments)
data = json.loads(raw)
print(data["city"])
```

### 课内可运行：在流中检测结束标记

```python run
def events():
    yield {"type": "text", "v": "思考"}
    yield {"type": "text", "v": "完成"}
    yield {"type": "end"}

for ev in events():
    if ev["type"] == "end":
        break
    print(ev.get("v", ""))
```


## 易错点

- **每片都 `json.loads`**：分片不是合法 JSON，必须缓冲到完整对象。
- **忘记 `flush=True`**：终端可能迟迟不显示；生产环境写 WebSocket 帧。
- **流式与工具交织**：同一条回复里可能先 text 后 tool_use；状态机要分类型处理。
- **把流式当最终测试依据**：单元测试仍应对完整消息断言；流式只做集成/手工测。

```python run raises=JSONDecodeError
import json

chunks = ['{"tool": "weather", "args": {', '"city": "上海"', "}"]
buffer = ""
print("模拟工具参数分片到达", len(chunks), "片")
for i, piece in enumerate(chunks, 1):
    buffer += piece
    print(f"片 {i} 后缓冲长度", len(buffer), "尾部", repr(buffer[-12:]))
print("尚未闭合就 json.loads")
json.loads(buffer)
```

流式工具调用里每片 append 后缓冲仍可能不是合法 JSON；打印每步长度与尾部片段，再对未闭合字符串 `loads` 会得到 `JSONDecodeError`，说明必须等缓冲完整或做增量解析器。

## 对照

| 模式 | Python 生成器 | JavaScript | Java |
|---|---|---|---|
| 增量消费 | `for x in gen` | `for await` | `Stream` |
| 累积字符串 | `list` + `join` | 数组 `join` | `StringBuilder` |
| SDK 流 | `stream=True` 事件 | SSE / fetch stream | reactive stream |

## 读代码

`examples/agent/minimal_agent.py` 默认 **非流式** `client.messages.create(...)`，一次拿全 `resp.content`。读流式版时关注三点：

1. `stream = client.messages.stream(...)` 或 `create(..., stream=True)`（以 SDK 文档为准，核对日期 2026-10-18 的 `anthropic` 包 API）。
2. 循环 `for event in stream` 累积 `text` 块；`tool_use` 块可能在流末尾才完整。
3. 工具执行仍调用本地 `TOOL_FUNCTIONS[name](**inputs)`，与 23.1 相同；流式只改**接收**方式。

阶段 23 包 **`run_tool` 与流无关**：

```python
from mini_agent import run_tool

# 流式 Agent 在拼完 tool_use.input 后调用
result = run_tool("echo", text="chunked")
```

验证包未破坏：

```bash
uv run pytest examples/项目/23-mini-agent包/test_mini_agent.py -q
```

运行完整 Agent（需 API Key，非 CI 必跑）：

```bash
uv run examples/agent/minimal_agent.py
```

## 练习

### 练习 1：生成器列表

```python exercise id=s23-l03-stream
# --- starter ---
def stream():
    return iter([])
# --- solution ---
def stream():
    yield "a"
# --- check ---
assert list(stream()) == ["a"]
```

### 练习 2：拼接分片

```python exercise id=s23-l03-join
# --- starter ---
def join_fragments(parts: list[str]) -> str:
    return ""
# --- solution ---
def join_fragments(parts: list[str]) -> str:
    return "".join(parts)
# --- check ---
assert join_fragments(["ab", "cd"]) == "abcd"
```

### 测试策略

流式路径适合手工或集成测试；单元测试仍对 `run_tool("echo", text="hi")` 断言确定性结果。不要在 CI 中依赖真实 LLM 流式事件；包测试保持离线可重复。

终端 UI 可在每个 text delta 后 `flush`，避免用户以为卡死。若同时开流式与工具，建议用小型状态机：`COLLECT_TEXT` / `COLLECT_TOOL_JSON` 两态切换，单元测试可针对状态机纯函数断言。

流结束后再调用 `run_tool`，与 23.1 非流式路径汇合，避免重复实现工具逻辑。


## 小结

- 流式用生成器/事件迭代表达；完整 tool JSON 需缓冲后再解析。
- minimal_agent 非流式易测；产品 UI 常用流式打印。
- `mini_agent.run_tool` 在拼好参数后调用，与是否流式无关。
- 包测试：`uv run pytest examples/项目/23-mini-agent包/test_mini_agent.py -q`。
- 流式首字延迟（TTFT）是体验指标，与总 token 数分开看。
- 用户中断（Ctrl+C）时要关闭 SDK 流，释放连接。
- 重放测试可用录制的 event 列表喂给处理函数。
- 工具参数 JSON 完整后再校验 schema，避免半片解析。
- 非流式 `messages.create` 更易设断点调试。
- 流式打印别忘记最终换行，日志工具才易读。
- 与 19 课异步 IO 不同，流式是消费侧迭代模式。
- SSE 与 WebSocket 是另一种推送形态，LLM SDK 已封装字节流。
- 累积完整回复后再写数据库，避免半条消息入库。
- 日志脱敏：流式文本也可能含用户隐私，注意裁剪。
- 回放 fixture 放在 `tests/` 而非课内 `python run` 块。
- 核对日期 2026-10-18：流式 API 字段以当前 `anthropic` SDK 文档为准。
- 打印进度条时用 `\r` 覆写行时注意终端兼容性。
- 完整消息入库前校验 UTF-8，避免半包编码错误。
- 流式与工具并存时，先结束 text 块再进入 tool 解析更安全。
- 为 `run_tool` 写集成测试时仍用非流式假消息，降低测试复杂度。
- 文档化「流式关闭」回调，避免客户端断开留下半开连接。
- 流式演示脚本与 `test_mini_agent.py` 分目录，避免 CI 误调外网。
