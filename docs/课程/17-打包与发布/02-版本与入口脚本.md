# 17.2 版本与入口脚本

> 前置：5.2 包 · 约 35 分钟 · 官方对应：[entry points](https://packaging.python.org/en/latest/specifications/entry-points/)、[console scripts](https://packaging.python.org/en/latest/specifications/entry-points/#entry-points) · 核对日期 2026-10-18

## 目标

- 在 `pyproject.toml` 用 `[project.scripts]` 或等价 entry point 声明 CLI 命令名。
- 模块内提供 `main()` 并返回 **int 退出码**，入口用 `SystemExit(main())`。
- 理解可编辑安装后命令出现在 `.venv/bin/`，与 `uv run python -m` 的关系。
- 对照 `logstats_pkg.cli.main` 如何被测试与将来被 console script 调用。

## 核心概念

### main 返回码

Unix 约定：0 成功，非 0 失败。阶段 17 CLI：

```python run
def main(code: int = 0) -> int:
    print("cli")
    return code

assert main() == 0
raise SystemExit(main())
```

课内 `raise SystemExit(main())` 演示脚本入口；`check_course` 把非 0 退出视为失败，故示例用 0。

### 从 Path 到 argv 风格

[`cli.py`](../../../examples/项目/17-CLI打包/logstats_pkg/cli.py) 的 `main(path: Path)` 适合测试直接传 `tmp_path` 文件；安装为脚本时常包装一层：

```python fragment
def console_main() -> int:
    import sys
    from pathlib import Path
    if len(sys.argv) < 2:
        print("usage: logstats FILE", file=sys.stderr)
        return 2
    return main(Path(sys.argv[1]))
```

pyproject 声明：

```toml
[project.scripts]
logstats = "logstats_pkg.cli:console_main"
```

课内模拟映射：

```python run
entry_points = {"logstats": "logstats_pkg.cli:console_main"}
module, func = entry_points["logstats"].split(":")
assert module == "logstats_pkg.cli"
assert func == "console_main"
```

### 版本号单一来源

`[project] version = "0.1.0"` 应与 git tag / 发布说明一致。进阶做法是在 `__init__.py` 暴露 `__version__` 并从 importlib.metadata 读取，避免两处手写。

```python run
version = "0.1.0"
parts = version.split(".")
assert len(parts) == 3 and parts[0].isdigit()
print(version)
```

## 易错点

- **entry point 指向不存在的函数**：安装成功但命令报 ImportError。
- **main 打印却不返回 int**：shell 看不到正确退出码。
- **在 import 时 parse_args**：pytest 与 `uv run` 会误解析参数（14.4、15.1）。
- **命令名与 PyPI 包名混淆**：PyPI 上 `logstats` 可能已被占用，包名常加前缀如 `jdp-logstats`。

```python run
def bad_main():
    return None

code = bad_main()
assert code is None  # shell 会把 None 当成 0 或异常，取决于入口包装
```

应显式 `return 0`。

**`logstats_pkg/__init__.py`**

```python
from logstats_pkg.cli import main

__all__ = ["main"]
```

包对外导出 `main`，便于 `from logstats_pkg import main` 写测试。

**`test_package.py`**

```python
from logstats_pkg.cli import count_levels, main

def test_main(tmp_path: Path) -> None:
    p = tmp_path / "x.log"
    p.write_text("INFO x\n", encoding="utf-8")
    assert main(p) == 0
```

### 练习 2：`exit_message`

实现 `exit_message(ok: bool) -> int`：`ok` 为真返回 0，否则返回 1（不写 print）。

```python exercise id=s17-l02-exit
# --- starter ---
def exit_message(ok: bool) -> int:
    return 0
# --- solution ---
def exit_message(ok: bool) -> int:
    return 0 if ok else 1
# --- check ---
assert exit_message(True) == 0
assert exit_message(False) == 1
```

## 小结

- console_scripts 把模块函数注册为 shell 命令；函数应返回退出码。
- `logstats_pkg.cli.main` 是测试友好的核心；argv 包装层可薄。
- 版本与 entry point 写在 pyproject，安装后从 `.venv/bin` 验证。

`console_main` 与 `main(Path)` 分层是常见模式：内层可测，外层适配 shell。

版本号建议遵循 semver：破坏兼容升 major，新功能升 minor，修复升 patch。

`uv run python -c "import logstats_pkg; ..."` 在未安装 wheel 时依赖 conftest 路径，与真实用户 `pip install` 不同。

安装后可用 `which logstats` 确认 entry point 落在当前 venv 的 `bin` 下。

测试 `main` 时继续用 `tmp_path` 写日志，不必构建 wheel。

entry point 字符串必须是 `module:callable`，冒号两侧不能有空格。

若 CLI 需要子命令，可在 console_main 里再调 argparse，内层仍保持纯函数。

`raise SystemExit(main())` 与 `sys.exit(main())` 等价；脚本模板沿用 14 课写法。

`__all__` 控制 `from logstats_pkg import *` 的公开名；entry point 仍可指向未列入 `__all__` 的函数。

多入口（CLI + 库 API）时，`main` 供库调用，`console_main` 仅供 scripts 表。

版本与依赖在 pyproject 一处维护，wheel METADATA 自动同步，减少发版手误。

测试不经过 entry point 时，仍能覆盖 99% 逻辑；console 层留一条冒烟即可。

核对日期 2026-10-18：entry points 规范以 packaging.python.org 为准。

`importlib.metadata.version("pkg")` 可在运行时读已安装分发版本，避免硬编码字符串。

`logstats_pkg.__init__` 重导出 `main`，方便测试与文档示例统一入口。

CLI 参数将来扩展时，优先加 optional 参数，保持 `main(Path)` 单文件参数的简单测试。

shebang `#!/usr/bin/env python3` 在可编辑脚本里常见；entry point 由安装器生成包装脚本，不必手写 shebang。

Windows 上 entry point 生成 `.exe` 包装；纯 Python wheel 仍跨平台。

文档示例命令与 14 课 `logstats.py` 对照，理解 argv 与 Path 两种入口差异。

`test_main` 断言退出码 0，与 shell 调用 `logstats file.log` 的期望一致。

entry point 名称尽量短、全小写、无空格，符合 Unix 命令习惯。
