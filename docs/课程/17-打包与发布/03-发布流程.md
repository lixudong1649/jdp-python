# 17.3 发布流程（讲解）

> 前置：17.1 wheel · 约 30 分钟 · 官方对应：[TestPyPI 指南](https://packaging.python.org/en/latest/guides/using-testpypi/)、[发布到 PyPI](https://packaging.python.org/en/latest/tutorials/packaging-project/#uploading-the-distribution-archives) · 核对日期 2026-10-18

## 目标

- 了解从 `uv build` 到上传 **TestPyPI / PyPI** 的步骤与审计要点。
- 知道 API token 应放在环境变量或 CI secret，**绝不**提交进 git。
- 理解包名在 PyPI **全局唯一**，与本仓库课程示例名可能冲突。
- 明确本课程**不要求**真实 upload；以本地 build + 测试为主。

## 核心概念

### 本地发布演练流水线

```text
1. 跑通 pytest / ruff / mypy
2. uv build  →  dist/*.whl + *.tar.gz
3. twine check dist/*   （或 uv publish 内置检查）
4. twine upload --repository testpypi dist/*
5. 在新 venv 里 pip install 刚上传的包做冒烟
```

课内用 Python 列表表示顺序：

```python run
steps = [
    ("test", "uv run pytest -q"),
    ("build", "uv build"),
    ("check", "twine check dist/*"),
    ("upload", "uv publish --repository testpypi"),
    ("smoke", "pip install dist/*.whl && logstats --help"),
]
gates = {name: idx for idx, (name, _) in enumerate(steps, 1)}
for i, (name, cmd) in enumerate(steps, 1):
    verb = cmd.split()[0]
    print(i, name, "first token", verb)
build_idx = gates["build"]
upload_idx = gates["upload"]
print("upload index", upload_idx, "build index", build_idx, "order ok", build_idx < upload_idx)
print("smoke after upload", gates["smoke"] > upload_idx)
```

发布流水线把测试放在最前、冒烟安装放在最后；`gates` 把步骤名映射到序号，输出应显示 build 在 upload 之前、smoke 在 upload 之后，避免未 build 就 upload。

### TestPyPI 与生产 PyPI

| 仓库 | 用途 | 风险 |
|---|---|---|
| TestPyPI | 练习 upload、CI 集成 | 低，可删包重传（有配额） |
| PyPI | 正式用户 `pip install` | 高，版本不可覆盖同 tag |

课程建议：只在 TestPyPI 演练；真发布需 changelog、许可证、安全审计。

```python run
repos = {
    "testpypi": {"url": "https://test.pypi.org/legacy/", "risk": "low", "immutable": False},
    "pypi": {"url": "https://upload.pypi.org/legacy/", "risk": "high", "immutable": True},
}
for name, meta in repos.items():
    host = meta["url"].split("/")[2]
    print(name, "host", host, "risk", meta["risk"], "immutable", meta["immutable"])
practice_host = repos["testpypi"]["url"].split("/")[2]
print("practice uploads should target", practice_host)
prod = repos["pypi"]
print("production needs immutable versions", prod["immutable"])
print("indexes differ", practice_host != prod["url"].split("/")[2])
```

TestPyPI 与生产 PyPI 的 URL、风险与「版本是否可覆盖」不同；课内只打印元数据对比，练习 upload 应只指向 TestPyPI 主机名，生产索引要求版本不可重复上传。

### 凭证与环境变量

```bash
export UV_PUBLISH_TOKEN="pypi-..."   # 示例名，以 uv 文档为准
uv publish --publish-url https://test.pypi.org/legacy/
```

课内强调原则，不执行上传：

```python run
import os

WATCH = ("UV_PUBLISH_TOKEN", "TWINE_PASSWORD")


def publish_env_status() -> dict[str, str]:
    out: dict[str, str] = {}
    for key in WATCH:
        raw = os.environ.get(key)
        out[key] = "set" if raw else "missing"
    return out


def redact_log(status: dict[str, str]) -> str:
    token_state = status.get("UV_PUBLISH_TOKEN", "missing")
    token_field = "***" if token_state == "set" else "none"
    return f"upload ok token={token_field}"


status = publish_env_status()
masked = {k: ("***" if v == "set" else v) for k, v in status.items()}
log_line = redact_log(status)
for key in WATCH:
    print(key, status[key], "log_field", masked[key])
print("secrets only via env", all(k in status for k in WATCH))
print("safe log", log_line)
print("any unset", sum(1 for v in status.values() if v == "missing"))
```

真实 token 只应出现在环境变量或 CI secret；`publish_env_status` 读出是否已设置，`redact_log` 把日志里的 token 打成 `***`，避免把 `.pypirc` 或明文 secret 写进仓库。

### 本仓库边界

- 根 `pyproject` 描述的是**学习仓**，不是要上 PyPI 的产品包。
- 阶段 17 `logstats_pkg` 用于理解结构；若真要发布，应拆到独立仓库并改唯一包名。

```python run
import io
import re
import zipfile

def build_wheel(name: str, version: str, leak_token: str | None = None) -> bytes:
    pkg = name.replace("-", "_")
    meta = f"Name: {name}\nVersion: {version}\n"
    body = b"# package\n"
    if leak_token:
        body = f"# debug {leak_token}\n".encode()
    record = f"{pkg}/__init__.py,,\n{name}-{version}.dist-info/METADATA,,\n"
    buf = io.BytesIO()
    with zipfile.ZipFile(buf, "w") as zf:
        zf.writestr(f"{name}-{version}.dist-info/METADATA", meta)
        zf.writestr(f"{pkg}/__init__.py", body)
        zf.writestr(f"{name}-{version}.dist-info/RECORD", record)
    return buf.getvalue()


def preflight_wheel(wheel_bytes: bytes, filename: str) -> dict[str, bool]:
    token_re = re.compile(rb"pypi-[A-Za-z0-9_-]{20,}")
    ok_version = bool(re.fullmatch(r"\d+\.\d+\.\d+", filename.split("-")[1]))
    with zipfile.ZipFile(io.BytesIO(wheel_bytes)) as zf:
        meta_name = next(n for n in zf.namelist() if n.endswith(".dist-info/METADATA"))
        meta = zf.read(meta_name).decode()
        name_line = next(ln for ln in meta.splitlines() if ln.startswith("Name: "))
        ver_line = next(ln for ln in meta.splitlines() if ln.startswith("Version: "))
        wheel_name = name_line.split(": ", 1)[1]
        wheel_ver = ver_line.split(": ", 1)[1]
        name_match = filename.startswith(f"{wheel_name}-{wheel_ver}")
        blob = b"".join(zf.read(n) for n in zf.namelist())
        token_free = token_re.search(blob) is None
    return {
        "semver_in_filename": ok_version,
        "metadata_matches_filename": name_match,
        "no_token_in_wheel": token_free,
    }


good = build_wheel("demo-pkg", "1.0.0")
bad = build_wheel("demo-pkg", "1.0.0", leak_token="pypi-AgEIcHlwaS5vcmcCJD...")
good_report = preflight_wheel(good, "demo_pkg-1.0.0-py3-none-any.whl")
bad_report = preflight_wheel(bad, "demo_pkg-1.0.0-py3-none-any.whl")
print("good wheel checks", good_report)
print("good all pass", all(good_report.values()))
print("bad token check", bad_report["no_token_in_wheel"])
print("bad blocked", not bad_report["no_token_in_wheel"])
```

`preflight_wheel` 从 zip 里读出 `METADATA` 与全部字节，核对文件名里的版本、`Name`/`Version` 是否与 wheel 名一致，并扫描疑似 PyPI token。好包三项全为 `True`，故意塞进 `pypi-...` 的包会在 `no_token_in_wheel` 上失败，发布前就应拦下而不是上传后再后悔。


## 易错点

- **泄露 token**：`.pypirc`、截图、日志里带密码；用 CI masked variables。
- **未测 wheel 就上传**：应在新虚拟环境 `pip install dist/xxx.whl` 再跑冒烟测试。
- **版本号未递增**：PyPI 拒绝重复版本；遵循 semver 或 calver 团队规范。
- **许可证与元数据缺失**：`pyproject` 应含 `license` / `readme` / `authors`（正式项目）。

```python run raises=ValueError
def parse_semver(v: str) -> tuple[int, int, int]:
    a, b, c = v.split(".")
    return int(a), int(b), int(c)

assert parse_semver("0.1.0") == (0, 1, 0)
parse_semver("0.1")  # 课内：段数不足
```

| 步骤 | Python (PyPI) | npm | Maven Central |
|---|---|---|---|
| 构建 | uv build / python -m build | npm publish (pack) | mvn deploy |
| 演练仓库 | TestPyPI | npm test registry | Sonatype OSS |
| 认证 | API token | npm token | GPG + token |
| 唯一性 | 包名全局 | scope @org | groupId |

### 凭证与 CI 示意

GitHub Actions 典型步骤：checkout → `uv sync --group dev` → pytest → build → `twine check` → upload（secret 存 `PYPI_API_TOKEN`）。

不要在 issue、截图或课程作业里粘贴 token；泄露后立刻在 PyPI 撤销并轮换。

本地 `.pypirc` 若存在，应加入 `.gitignore`；本仓库不提供该文件模板。

### 与 17.1 / 17.2 的衔接

17.1 解决「包里有什么」；17.2 解决「用户命令行怎么调」；本课解决「如何安全地把产物交给索引服务器」。

缺任何一环都可能出现「能 build、能装、但用户装不到」或「装了却跑不起来」——测试贯穿三课。

### 常见失败场景

包名已被占用：上传被拒，改名或加组织前缀。

元数据 markdown 错误：`twine check` 失败，修 `pyproject` 的 readme 字段。

忘记 bump version：重复版本无法上传，需发 0.1.1。

在错误索引上传：把 TestPyPI token 打到 production URL，立即下架并检查是否泄露。

维护者可在 Release 页面附 wheel 附件，但 PyPI 仍是用户 `pip install` 的默认来源。

核对日期 2026-10-18：本课描述的上传工具与 URL 以 packaging 官方指南为准。

学生练习建议只用 TestPyPI；生产 PyPI 需维护者审核与版本策略。

Yank（标记有问题版本）比删版本更符合 PyPI 政策；用户仍不应装 yanked 版。

组织账号可管理多个维护者；课程个人练习用个人账号即可。

发版笔记可写在 GitHub Release，与 PyPI 项目描述互补。

### 练习 2：`ready_to_publish`

实现 `ready_to_publish(tests_ok: bool, version_bumped: bool) -> bool`：两者都为真才返回 `True`。

```python exercise id=s17-l03-ready
# --- starter ---
def ready_to_publish(tests_ok: bool, version_bumped: bool) -> bool:
    return False
# --- solution ---
def ready_to_publish(tests_ok: bool, version_bumped: bool) -> bool:
    return tests_ok and version_bumped
# --- check ---
assert ready_to_publish(True, True) is True
assert ready_to_publish(True, False) is False
```


## 小结

- 发布 = 测试绿 → build → check → upload TestPyPI → 干净环境冒烟。
- 凭证只放 secret；本课程停在本地 wheel 与文档流程。
- `logstats_pkg` + pytest 是上传前的最小质量门槛。

发布前 checklist：许可证、README、版本唯一、changelog、CI 绿、无密钥在 diff 里。

PyPI 禁止重复上传同一版本；修 bug 必须 bump patch 再发。

TestPyPI 账号与生产 PyPI 分开注册；token 也分开保管。

本课程仓库不上传；你在个人练习仓库可跟官方指南走完 TestPyPI 全流程。

`twine check` 验证元数据字段完整，能在上传前发现 README 渲染错误。

发布后在新 venv `pip install yourpkg==x.y.z` 跑 smoke test，比只信本地 editable 更贴近用户。

供应链安全：启用 2FA on PyPI，CI 用有限 scope 的 token。

误发版本无法覆盖同名 tag；只能发新版本并在文档中说明废弃版本。

练习仓库可用 `yourname-logstats` 之类唯一包名，避免与 PyPI 已有项目冲突。

`uv publish` 封装了 twine 常用参数；无论工具，原则都是 build → check → upload。

课程结束标准：理解流程 + 本地 pytest 绿，不要求账号上有真实包。

回顾 15–17：测试保障行为，工具链保障质量，打包交付形态。

发布说明可附 `uv run pytest` 与 Python 版本要求，降低用户环境差异。

若将来开源，在 README 写明「课程示例，非生产维护」，管理用户预期。

阶段 17 完成后，你应能向他人解释 wheel 与上传的区别，即使从未点过 upload 按钮。

重复一遍安全原则：token 仅环境变量，日志里打码，历史 commit 泄露要轮换密钥。

上传前在 dist 目录 `ls -l` 确认只有预期版本文件，避免把旧 beta 一并上传。

维护 long description 时，README 与 PyPI 页面共用同一份 markdown 可减少漂移。

课程不要求注册 PyPI 账号；理解流程即可毕业本阶段。

真上传前让同事 review `pyproject` 的 name/version/dependencies 三角关系。

TestPyPI 包可随意删除重传练习；生产包删除受限，发布要更谨慎。

练习 `ready_to_publish` 布尔逻辑，对应团队发版 checklist 的两项硬门槛。

发布是流程终点，不是学习终点；后续 Web/Agent 课会继续用同一套测试与打包观念。
