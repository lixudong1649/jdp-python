# 24.4 导入系统

> 前置：5.1 模块与 import、24.3 内存 · 约 40 分钟 · 官方对应：[导入系统](https://docs.python.org/zh-cn/3/reference/import.html) · 核对日期 2026-10-18

## 目标

- 理解 **`import` 执行模块顶层代码** 一次，结果缓存到 **`sys.modules`**。
- 区分 **绝对导入** 与 **包相对导入**（`from .tools import REGISTRY`），读懂 `__package__`。
- 认识 **循环 import** 导致“半初始化模块”的症状与修复（延迟导入、重构依赖）。
- 读阶段 23 包结构：`mini_agent` 如何通过导入链暴露 `run_tool`。
- 知道 `if __name__ == "__main__"` 与 `-m` 在导入行为上的差别。

## 核心概念

### sys.modules 缓存

```python run
import sys

before = "json" in sys.modules
print("首次 import 前 json 在 modules?", before)
import json

after = sys.modules["json"] is json
print("import 后缓存命中?", after)
print("json 模块文件", getattr(json, "__file__", "n/a"))
print("sys.modules 含 json", "json" in sys.modules)
print("loads 可用", json.loads('{"k": 1}'))
```

标准库模块首次导入后会写入 `sys.modules`，再次 `import json` 只返回缓存对象，不会重复执行模块顶层。输出对比导入前后是否在缓存里，以及 `loads` 仍可用。

### 再次 import 不重跑顶层

```python run
import importlib
import sys

name = "json"
mod1 = importlib.import_module(name)
mod2 = importlib.import_module(name)
print(mod1 is mod2)
```

### 包与 `__init__.py` 重导出

```python run
# 模拟包 __init__ 重导出：真实代码见 mini_agent/__init__.py
_public = {
    "run_tool": lambda name, **kw: kw.get("text", ""),
    "VERSION": "0.1.0",
}


class MiniPkg:
    def __getattr__(self, name: str):
        if name in _public:
            return _public[name]
        raise AttributeError(name)


pkg = MiniPkg()
print("导出键", sorted(_public))
print("run_tool", pkg.run_tool("echo", text="hi"))
print("VERSION", pkg.VERSION)
print("from pkg import run_tool 等价于取 __init__ 属性")
```

包对外只暴露 `__all__` 或 `__init__` 里绑定的名字；课内用字典 + `__getattr__` 模拟 `from mini_agent import run_tool` 的查找链，输出列出公开符号与调用结果。

### import 搜索路径

```python run
import sys
from pathlib import Path

head = sys.path[:4]
print("sys.path 前四项")
for i, entry in enumerate(head):
    label = "cwd" if entry == "" else entry
    kind = "site-packages" if "site-packages" in entry else "other"
    print(i, label, "->", kind)
print("共", len(sys.path), "项")
print("首项是空串?", sys.path[0] == "")
print("可写目录在 path?", any(Path(p or ".").exists() for p in head))
```

`sys.path` 决定 `import` 查找顺序：当前工作目录（空串）、虚拟环境 site-packages 等。打印前几项与类型标签，便于理解「同名本地文件遮蔽标准库」为何发生。

### 动态 import

```python run
import importlib
import sys

name = "math"
first = importlib.import_module(name)
second = importlib.import_module(name)
print("两次 import_module 同一对象?", first is second)
print("sqrt(9)", first.sqrt(9))
print("已在 sys.modules", name in sys.modules)
print("模块名", first.__name__)
print("spec", first.__spec__.name if first.__spec__ else None)
```

`importlib.import_module` 与语句 `import math` 共用 `sys.modules` 缓存；动态插件加载时常用此 API，输出确认第二次返回同一模块对象。

## 易错点

- **循环 import**：`a.py` import `b`，`b.py` import `a`，一侧读到未完成的属性。
- **相对导入在脚本直接运行失败**：`python tools.py` 无包上下文；应 `python -m package` 或从项目根用 pytest。
- **修改 `sys.path` 掩盖结构问题**：优先正规包布局与 `uv` 环境。
- **同名模块遮蔽**：本地文件 `json.py` 会挡住标准库 `json`。

```python run raises=ModuleNotFoundError
import importlib
import sys

bogus = "definitely_not_a_real_module_24_04"
print("准备 import", bogus)
print("当前 path 长度", len(sys.path))
print("已在 modules?", bogus in sys.modules)
try:
    importlib.import_module(bogus)
except ModuleNotFoundError as err:
    print("第一次失败", err)
    raise
```

故意 import 不存在的模块名，会先打印候选名与 `sys.path` 规模，再把 `ModuleNotFoundError` 原样抛出。错误消息里的模块名应与字符串一致，便于区分 typo 与未安装依赖。

## 对照

| 概念 | Python | Node.js | Java |
|---|---|---|---|
| 模块缓存 | `sys.modules` | `require.cache` | `ClassLoader` |
| 包 | 目录 + `__init__.py` | `package.json` | JAR 包 |
| 相对导入 | `from . import x` | `./x` | 同包 |
| 入口 | `-m` 模块 | `node path` | `main` |

## 读代码

阶段 23 包导入链：

```python
# mini_agent/__init__.py
from mini_agent.runner import run_tool
from mini_agent.tools import REGISTRY, tool

__all__ = ["REGISTRY", "run_tool", "tool"]
```

```python
# mini_agent/runner.py
from mini_agent.tools import REGISTRY


def run_tool(name: str, **kwargs: object) -> object:
    if name not in REGISTRY:
        raise KeyError(name)
    return REGISTRY[name](**kwargs)
```

```python
# test_mini_agent.py（节选）
from mini_agent import run_tool

def test_run_tool() -> None:
    assert run_tool("echo", text="hi") == "hi"
```

读法：

1. `import mini_agent` 先执行 `__init__.py`，拉入 `runner` 与 `tools`。
2. `tools.py` 顶层定义 `REGISTRY` 并注册 `echo`；导入顺序保证 `run_tool` 调用前已注册。
3. `from mini_agent import run_tool` 是包对外 API；测试不必知道 `runner` 子模块。
4. 若在 `tools.py` 顶层 `from mini_agent.runner import run_tool` 会形成 **循环 import**，应避免。
5. pytest 从项目根运行，`examples/项目/23-mini-agent包` 在 `sys.path`（经 conftest 或包布局）可找到 `mini_agent`。

验证：

```bash
uv run pytest examples/项目/23-mini-agent包/test_mini_agent.py -q
```

## 练习

### 练习 1：模块名

```python exercise id=s24-l04-imp
# --- starter ---
name = "sys"
# --- solution ---
import json

name = json.__name__
# --- check ---
assert name == "json"
```

### 练习 2：从缓存取模块

```python exercise id=s24-l04-mod
# --- starter ---
def cached_name(mod_name: str) -> str:
    return ""
# --- solution ---
import importlib
import sys

def cached_name(mod_name: str) -> str:
    if mod_name not in sys.modules:
        importlib.import_module(mod_name)
    return sys.modules[mod_name].__name__
# --- check ---
assert cached_name("math") == "math"
```

### pytest 与包路径

`examples/项目/conftest.py` 可能调整 `sys.path`，使 `mini_agent` 可被导入；读测试失败堆栈时先看 `ModuleNotFoundError` 是否因从错误目录执行 pytest。始终在仓库根运行课文中的 `uv run pytest ...` 命令。

`importlib.reload` 仅 REPL 调试用，测试里 reload 会破坏单例假设。包内相对导入要求当前模块属于包；把代码当脚本直接跑时改用绝对导入或 `-m` 入口。

命名空间包（无 `__init__.py`）在 3.12 仍常见；本仓 `mini_agent` 使用显式 `__init__.py` 便于教学。


## 小结

- `import` 一次执行、永久缓存；调试循环依赖看 `sys.modules` 与导入顺序。
- 包用 `__init__.py` 收敛公开 API；阶段 23 是标准范例。
- 脚本入口用 `python -m` 或 pytest，避免相对导入踩坑。
- 读项目先扫 `import` 块，再追 `REGISTRY` 等单例初始化。
- `from pkg import *` 受 `__all__` 限制，显式导入更清晰。
- 延迟导入在函数内 `import heavy` 可缩短启动时间。
- zipimport 与常规目录包对学习者较少见，知道即可。
-  editable 安装（`uv pip install -e`）改变导入来源为源码树。
- 类型检查器与运行时的导入路径可能不同，mypy 用额外配置。
- 阶段 23 测试导入 `mini_agent` 验证包布局正确。
- `importlib.metadata` 读已安装包版本，运行时自查环境。
- 子包 `mini_agent.tools` 可单独测注册表，不必经 `__init__`。
- `PYTHONPATH` 临时改路径仅调试，项目应靠正规包结构。
- 核对日期 2026-10-18：PEP 451 导入钩子对初学者了解即可。
- `runpy.run_module` 与 `python -m` 等价入口，适合包内 `__main__.py`。
- 读 `ImportError` 消息时注意是缺包还是循环依赖后半句。
- _vendor 目录不要手动加入 `sys.path`，用依赖管理安装。
- `from __future__ import annotations` 推迟注解求值，不影响 import 顺序本身。
- 包资源读取优先 `importlib.resources`，少用手写路径拼接。
- 核对日期 2026-10-18：`mini_agent` 包名与 PyPI 全局包名冲突时改用项目前缀。
- `import *` 在库代码中避免，测试与 REPL 可例外。
- 显式 `__all__` 列表即包的公共契约，改时要同步文档。
- 顶层副作用应限于常量与注册，IO 放 `main` 或工厂函数。
- 理解 `sys.modules['mini_agent']` 在首次 import 后即缓存，便于调试断点。
- 阶段 23 课文测试命令：`uv run pytest examples/项目/23-mini-agent包/test_mini_agent.py -q`。
- 导入性能：大型项目可用 lazy import 缩短 CLI 冷启动，代价是首次调用更慢。
