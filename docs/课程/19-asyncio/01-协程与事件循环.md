## 核心概念

### async def 不是「立刻执行的函数」

调用 `async def` 函数不会跑函数体，而是返回协程对象，需由循环驱动到完成。

```python run
import inspect

async def fetch_token() -> str:
    return "tok-abc"

print(inspect.iscoroutinefunction(fetch_token))
coro = fetch_token()
print(type(coro).__name__, inspect.iscoroutine(coro))
coro.close()
```

`close()` 释放未 await 的协程，避免课内警告；真实代码应 `await` 或交给 `asyncio.run`。

### await 的语义

`await expr` 要求 `expr` 是可等待对象（协程、Task、Future 等）。等待期间事件循环可运行其他就绪任务。

本地完整驱动示例（请在仓库根用 CPython 执行，浏览器块中为静态说明）：

```python
import asyncio

async def main() -> int:
    await asyncio.sleep(0)
    return 42

print(asyncio.run(main()))
```

### 与线程的对比（选型直觉）

| 模型 | 切换成本 | 适合 |
|---|---|---|
| 线程 | OS 调度，栈较大 | 阻塞库多、改造少 |
| asyncio | 协作式，单线程循环 | 大量 I/O、原生 async SDK |

同一进程里可以 **同时** 存在线程池与事件循环（例如 `asyncio.to_thread`），但主循环仍应保持非阻塞；新手常见误区是在 `async def main` 里起四个线程各跑 CPU 密集循环，却期待与 free-threaded 相同的加速。

```python run
# 同步函数里调用 async 函数的错误姿势：得到 coroutine 而非结果
async def answer() -> int:
    return 7

maybe = answer()
print(maybe.__class__.__name__ != "int")
maybe.close()
```

## 易错点

- **忘记 await**：拿到 coroutine 对象，条件判断永远「真」，且可能触发 `RuntimeWarning`。
- **在 async 里 `time.sleep` 或同步 `requests.get`**：卡住整个循环；用 `asyncio.sleep` 或 async HTTP 客户端。
- **没有入口 `asyncio.run` / 已有循环里再 `run`**：嵌套 `run` 会报错；Jupyter 等环境可能已有循环。
- **把 CPU 密集塞进 async 函数**：应 `asyncio.to_thread`（3.9+）或进程池，否则阻塞循环。

演示「把协程当普通值」的逻辑错误：

```python run raises=TypeError
async def value() -> int:
    return 1

x = value()
print(x + 1)
```

## 读代码

`examples/项目/19-异步minimal_agent/async_agent.py` 模拟 **异步 HTTP 客户端** 完成一次补全：

```python source=examples/项目/19-异步minimal_agent/async_agent.py
"""异步版 minimal_agent 骨架（模拟 HTTP 客户端，阶段 19）。"""
from __future__ import annotations

import asyncio
from dataclasses import dataclass, field


class AgentError(ValueError):
    """业务层输入或调用错误。"""


@dataclass
class FakeResponse:
    text: str
    model: str = "fake-mini"


@dataclass
class AgentSession:
    history: list[str] = field(default_factory=list)

    def record(self, prompt: str, reply: str) -> None:
        self.history.append(f"{prompt} -> {reply}")


class FakeAsyncClient:
    def __init__(self, *, latency: float = 0.0) -> None:
        self.latency = latency

    async def complete(self, prompt: str) -> FakeResponse:
        if not prompt.strip():
            raise AgentError("prompt 不能为空")
        if self.latency > 0:
            await asyncio.sleep(self.latency)
        else:
            await asyncio.sleep(0)
        return FakeResponse(text=f"echo:{prompt}")


async def run_once(prompt: str, *, client: FakeAsyncClient | None = None) -> str:
    owned = client or FakeAsyncClient()
    resp = await owned.complete(prompt)
    return resp.text


async def run_batch(prompts: list[str], *, client: FakeAsyncClient | None = None) -> list[str]:
    if not prompts:
        return []
    owned = client or FakeAsyncClient()
    tasks = [owned.complete(p) for p in prompts]
    responses = await asyncio.gather(*tasks)
    return [r.text for r in responses]


async def run_with_session(prompt: str, session: AgentSession) -> str:
    reply = await run_once(prompt)
    session.record(prompt, reply)
    return reply
```

- 第 12–16 行：`FakeResponse` 用 `dataclass` 承载响应体；`model` 字段预留与真实 SDK 对齐。
- 第 30–37 行：`complete` 是 **async 方法**；空 prompt 抛 `AgentError`，测试覆盖异常路径。
- 第 40–43 行：`run_once` 支持注入 `FakeAsyncClient`，便于单测替换实现。
- 第 46–52 行：`run_batch` 用 `asyncio.gather` 并发多个补全，顺序与 `prompts` 一致。
- 测试 `test_async_agent.py` 覆盖 `run_once`、`run_batch` 与 `AgentSession` 记录历史。

**协程 checklist**：

- 函数是否 `async def`？调用后是否得到 coroutine 而非最终结果？
- 是否在协程内 `await` 所有异步 I/O？
- 脚本入口是否计划用 `asyncio.run`（本地）？
- 是否避免在协程里调用长时间 `time.sleep`？
- 关闭未 await 的协程时是否调用 `close()`（课内练习）？

把 checklist 打印贴在显示器旁，直到你能不假思索区分「协程函数」与「协程对象」——这是读任何 async SDK 的门票。

官方文档中的 `asyncio.run` 示例请在本地终端运行；网站课内按钮仅验证协程对象与类型检查，以免 Pyodide 栈切换限制。

`await` 只能出现在 `async def` 函数体内；在普通 `def` 里写 `await` 会触发 `SyntaxError`，这与 JavaScript 的顶层 await 规则不同。

协程函数可以像普通函数一样被导入、赋值与传递，只是调用方式从 `f()` 变成「先拿 coroutine 再驱动」。

## 练习

### 练习 1：识别协程函数

实现 `is_async_fn(fn) -> bool`：若 `fn` 是由 `async def` 定义的函数返回 `True`。

```python exercise id=s19-l01-async
# --- starter ---
def is_async_fn(fn) -> bool:
    return False
# --- solution ---
import inspect

def is_async_fn(fn) -> bool:
    return inspect.iscoroutinefunction(fn)
# --- check ---
async def demo() -> None:
    pass

def sync() -> None:
    pass

assert is_async_fn(demo) is True
assert is_async_fn(sync) is False
```

### 练习 2：构造协程并安全关闭

实现 `make_greeting(name: str)`：定义并 **调用** 内部 `async def _inner()` 返回 `f"hi,{name}"`，返回协程对象（不 await）。调用方测试时会 `close()`。

```python exercise id=s19-l01-coro
# --- starter ---
def make_greeting(name: str):
    return None
# --- solution ---
def make_greeting(name: str):
    async def _inner() -> str:
        return f"hi,{name}"

    return _inner()
# --- check ---
import inspect

c = make_greeting("py")
assert inspect.iscoroutine(c)
c.close()
```

## 小结

- `async def` 定义协程函数；调用得到协程对象，必须被循环驱动。
- `await` 用于 I/O 型等待；阻塞调用会拖死事件循环。
- 阶段 19 项目展示最小 `async def` + `await` 客户端调用链；完整 `asyncio.run` 在本地 pytest 中验证。
- 浏览器课内只创建/检查协程对象；与 18 章线程模型互补。
- `FakeAsyncClient` 是阶段 22 真实 HTTP 客户端的简化替身。
- 读 traceback 时辨认 `coroutine was never awaited` 警告。
