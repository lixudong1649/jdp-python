## 4. 量化验收门槛
- **R7（阶段 12–24 的 `python run` 块，含 `raises=`）**：块内 `print(...)` 调用 ≥ 3 个，且其中 ≥ 50% 是「预写文字打印」→ 失败。「预写文字打印」= 这个 print 的每个参数都只来自块内写死的字面量，不经过任何真实计算。具体用 `ast` 判定，参数属于下列之一即算「字面量来源」：
  - 字符串/数字/布尔常量；不含 `{表达式}` 的 f-string；
  - 只含上述元素的 list / tuple / set / dict 字面量；
  - 被赋值为「字面量来源」的变量名；对「字面量来源」做下标取值、`.items()/.keys()/.values()` 遍历得到的循环变量；在两个「字面量来源」之间选择的条件表达式；对「字面量来源」取 `not`；元素和迭代对象都是「字面量来源」的推导式；
  - 块内定义、所有 `return` 都返回「字面量来源」的函数的调用结果（包括先建字面量列表再 `append` 字面量的情况）；
  - `hasattr(...)`、`sys.version` / `sys.version_info` 这类环境探测（它们说明不了本课行为）。
  其余（比较运算、算术运算、调用 `len`/`type`/`repr`/标准库函数/本课被演示的对象等）都算真实计算。
- **R7 先失败**：M1 只加 R7 和测试，不动课程，`check_course.py` 必须报出 T1、T2、T3 这 3 个块（贴输出）；同时列出 R7 报出的全部其他块。
- **T1–T3 改写**：每个有效代码（非空、非注释）≥ 8 行；输出必须由真实计算得到，并且能看出本课概念：
  - T1（19.2）：不用 `asyncio.run`（浏览器跑不了），用协程对象 + 手写驱动（`coro.send(None)` / `throw`）演示：一个子任务抛异常时，gather 默认语义下其他结果的去向，对比 TaskGroup「一个失败、同组其余被取消」；打印每个子任务的最终状态（完成 / 异常 / 被取消）。
  - T2（17.3）：真实构造一个最小 wheel（`zipfile` + `io.BytesIO`，含 `METADATA` 与 `RECORD`），写一个发布前检查函数检查版本号格式、`METADATA` 里的 Name/Version 与文件名是否一致、包内有没有疑似 token 的字符串，打印每项检查的结果；至少演示一个通过的包和一个被拦下的包。
  - T3（14.1，`raises=TypeError`）：先算出真实数据（如把 str 编码成 bytes 后的长度、逐字节十六进制），演示「先 encode 再拼接」能成功，再演示直接 `str + bytes` 抛 `TypeError`；不许有不带计算结果的空打印。
  - 每个块后紧跟 ≥ 2 句解释，内容和实际输出一致。
- **E 类块**：R7 不再报出；不许为了躲 R7 而把字面量包进 `str()`、拼接空串、改成 `sys.stdout.write`、删掉 print 降到 3 个以下等。改写后同样要计算并展示本课行为，每个 ≥ 8 行有效代码（原本已 ≥ 8 的不得减少），解释段落同步更新。
- **不降级**：每课正文 ≥ 150 行、`python run` ≥ 3、`python exercise`（不含 local）≥ 2；阶段 12–24 `python run` 总数 = 217；R1–R6 与 v2.3.1 的 13 块回归测试继续通过。
- **全量五条命令**：`uv run python tests/check_course.py`、`uv run pytest -q`、`uv run ruff check`、`cd site && npm run build`、`time perl -e 'alarm 900; exec @ARGV' -- npm --prefix site run verify`，全部通过。

## 九、硬门槛：里程碑提交必须带本里程碑的门禁证据（2026-10-19）

> 起因：jdp-python v2.2 与 v2.2.1 连续把多个里程碑攒到最后一次性分批提交（v2.2 的 M2–M6 提交时间同为 07:56:40；v2.2.1 的 M2 `cbb5d65`、M3 `e2cf1bc` 同为 08:03:33），每个里程碑没有单独跑检查。写进「禁止捷径」也没拦住，所以改成可机器核对的硬门槛。

**规则（原样贴进每份多里程碑 goal 的第 4 节和第 7 节）：**

1. 每个里程碑提交之前，必须先跑**本里程碑自己的**门禁命令；输出原样保存到证据文件（如 `docs/规划/证据/<版本>-M<n>.txt`，开头写命令和开始时间），并且**和该里程碑的改动放在同一次提交里**。没有证据文件的里程碑提交 = 不合格。
2. 相邻两个里程碑提交的提交时间间隔 **< 60 秒 = 自动不合格**，整轮打回，不讨论理由。
3. 不许改写历史来补救（rebase、amend、force-push 都不行）；已发生的违规只能在报告里如实写明。

**验收方法（Grok Bot）：**

```bash
git log --reverse --format='%h %ci %s' <goal提交>..HEAD
```

- 逐行算相邻里程碑提交的时间差，任一 < 60 秒判不合格；
- `git show --stat <每个里程碑提交>` 必须含本里程碑的证据文件，且证据里的命令与该里程碑的门禁一致、时间早于提交时间。
